## Phase 1 — Instrumentation and state foundation (M1-M3)

Start with the vertical slice in the project definition: local project registration, SQLite persistence, deterministic Git reconciliation, local MCP state reads, read-only dashboard, and automated tests. Extend it with objectives/tasks, decisions, immutable workflow versions, transactional event/state updates, runs, QA evidence, available local Codex telemetry, blockers, recent activity, and restart recovery. Add the memory substrate in this phase: independent class and temperature, stable identity and hashes, provenance, temporal validity and supersession, freshness markers, known-by state, context-transfer records, artifact references, and bounded HOT-memory scopes. This is a schema and deterministic-policy foundation, not a full automatic memory agent.

No worker orchestration or model/effort selectors are included in M1-M3. Codex's supported configuration pathway and role-specific model/effort fields are verified; Cathulu's selector surface is delivered separately in Phase 3 M9.

## Phase 2 — Memory lifecycle and context experiment (M4-M5)

Use the Phase 1 transfer ledger and memory metadata to measure context reintroduction, amplification, reuse, retrieval usefulness, and storage growth. M4 delivers selective SQL/FTS retrieval, a manual deterministic Memory Gardener for duplicate detection and reviewable promotion/demotion proposals, explicit provenance-linked consolidation candidates, extraction receipts, conservative reference-aware archiving, policy experiments, and storage/health metrics. Unique provenance and protected evidence remain traceable; retention stays configurable and disabled until an owner sets a minimum age. Later work may add summary/aggregate maintenance, telemetry compaction, or semantic indexing if usage and measured retrieval gaps justify them; any semantic index must return candidate IDs while SQLite remains authoritative. Graphify invalidation waits for a real graph snapshot source.

## Phase 3 — Codex-native worker delegation (M6-M9)

Reuse native Codex subagents and worktrees. M6 adds bounded typed task packets, hashed idempotency/correlation metadata, scope-checked memory and artifact links, and append-only delegation lifecycle events; it records owner handoff state without spawning agents. M7 adds structured worker reports and read-only dashboard presentation; M8 adds verifiable worktree isolation and supported worker telemetry. M9 adds a separate model/effort settings surface with explicit project, user-base, profile, and export-only targets; safe TOML preview/apply; preserved backups; and honest stored/written/effective status. Detailed milestones are in [PLAN-002](plans/PLAN-002-phase3-codex-delegation.md).

## Phase 4 — Durable scoped context (M10)

Add scopes and Sub-Overseers only after telemetry shows repeated cross-project reconstruction whose measured cost exceeds context maintenance and coordination overhead. Detailed entry evidence and acceptance criteria are in [PLAN-003](plans/PLAN-003-evidence-gated-scaling.md). No qualifying recurring cross-project workflow is currently available, so M10 is not eligible for the current work pattern. Backlog: exercise and evaluate a cross-repository handoff when real work naturally spans repositories; do not create a synthetic task for it. This deferred check does not block unrelated validation or maintenance, and M12-M14 retain their separate real-run evidence gates.

## Phase 5 — Graphify (M11; validated)

Integrate structural retrieval read-only, record graph snapshot identities/deltas, invalidate only memories tied to changed graph bases, and benchmark selected neighborhoods against simpler file/FTS retrieval. Graphify is a retrieval/freshness source, not a second memory authority. M11 completed on 2026-10-21: its local-only evidence gate passed using Graphify 0.9.82, schema 1, code-only extraction, and a pre-registered three-task comparison. Cathulu exposes bounded MCP path retrieval, SQLite snapshot identity/freshness, and selective graph-memory invalidation; the implementation passed Windows workspace tests and the local MCP release build. ## Phase 18 — Event-driven role orchestration (M39 gates validated; M40/M41 dispatcher and selective routing implemented; live project validation next)

M39 adds deterministic workflow gates: Main records a project-specific brief before PM preparation; PM records a bounded Worker plan; Main accepts it before Worker preparation; a Worker packet must match the accepted task; PM reviews Worker reports; Main reviews PM reports; unresolved escalations/owner approvals block PM closeout. This enforces durable order and scope. Ordinary MCP calls still do not authenticate the invoking Codex chat; app-server role turns use scoped capabilities.

M40/M41 now add a default-on local dispatcher with schema-v14 outbox/lease/thread bindings, schema-v17 idempotent role inbox/cursor, and schema-v18 single global Main binding/capability. Normal MCP startup starts only a background dispatcher thread; a hidden Codex app-server starts only when queued work or actionable events exist. The app-server disables globally configured MCP servers using process-only overrides; each role thread receives only its scoped Cathulu MCP config. Prepared independent PM/Worker assignments are submitted without waiting for turn completion. Worker events route to the active PM; PM plans/results/escalations route to Main; Main reviews and Owner decisions return only to the affected PM. Routine checkpoints remain passive. The Owner decision UI records intent only and never performs the approved action. Historical events are not replayed after migration, duplicate inbox delivery is idempotent, and active roles are not double-woken.
