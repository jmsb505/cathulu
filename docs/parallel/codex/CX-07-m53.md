## Findings — fix before policy registration

1. **Required review with zero eligible providers loses its reason.** In `src/routing_policy.rs`, `review_unmet` is true for required non-review work only when `eligible == 1`. When no providers are eligible, `unrouted(..., false, ...)` omits `RequiredReviewPending`: capacity queues with only `CapacityRetryAfter`, and non-capacity failures block without the review-pending rationale. Use the unmet-review condition for fewer than two eligible providers, and add zero-eligible capacity and transport fixtures. The expected outcome remains queue for capacity and block for transport; both must include `RequiredReviewPending`.

2. **Known zero quota reroutes without a reroute reason.** The zero-quota branch adds `CapacityRetryAfter` and a reset time, but leaves `Evaluation.unavailable` unset. If the preferred provider is exhausted and the alternate routes, the result omits `RoutingReason::Reroute`, contrary to CC-05 §2/§4. Preserve `UnavailableReason::Capacity` for this case unless the request already excludes the candidate, and assert the rationale in the quota fallback fixture.
