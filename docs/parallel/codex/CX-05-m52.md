## Delivered

- Added schema v22 for durable workspace leases and append-only lease events. Database constraints retain lease history, permit only valid status transitions, serialize writable leases to one per project, and keep path/role locks while a lease needs reconciliation.
- Added exact Git workspace checks: writers must use a clean linked worktree of the registered repository with the same Git common directory. A Worker may write; a Project Manager/coordinator is read-only; the registered project root cannot receive a writer lease.
- Bound provider attempts and role capabilities to the same active workspace lease. Capability authorization rechecks the live lease. Replaying an attempt key after its lease expires is refused.
- Added explicit provider credential-source eligibility. Unknown sources and sources absent from the permission manifest are rejected.
- Enforced one active provider session per logical role across providers. A v21 upgrade with cross-provider active-session collisions keeps both records but marks the ambiguous sessions `unknown`. A provider session cannot replace another while the role has an unresolved attempt; replacement revokes capabilities bound to the old session.
- Expiry, release or revocation with an unresolved attempt changes the attempt to `needs_reconcile`, revokes its capability and keeps the workspace locked until explicit terminal resolution. No automatic resubmit or filesystem cleanup is performed.
