## Delivered

- Schema v22 records workspace leases and append-only lease events. Writers use clean linked worktrees of the registered repository, share its Git common directory, and serialize to one writer lease per project. Project Managers receive read-only access.
- Provider attempts and role capabilities bind to the same active workspace lease. Capability authorization rechecks the lease. Unknown or unapproved credential sources are rejected. Cross-provider replacement waits until prior attempts are terminal.
- Expiry, release or revocation with unresolved attempts moves attempts to needs_reconcile, revokes capability, and preserves the workspace lock until explicit resolution. No automatic resubmit or filesystem cleanup occurs.
- Dispatcher admission resolves one exact active lease for each Worker/Project Manager assignment, derives its manifest from the lease and task scope, requires an explicitly allowed known credential source and network permission, binds the role capability to the same lease, and revalidates before process, thread/resume, and turn starts. Thread starts use the exact admitted workspace path.
- After issuing a capability, dispatcher refusals before `start_turn` revoke it through one shared guard for queued work and Project Manager inbox work. The last lease/capability admission check now precedes the `dispatched` mark. The guard preserves the capability once `start_turn` is called because a failed acknowledgement may mean the provider accepted the turn.
- Before either dispatcher route calls `start_turn`, it persists a Codex provider session and a unique provider attempt bound to the exact active lease, dispatch/inbox record, delegation and role capability. The attempt stores a hash of the prompt, not the prompt. A successful start acknowledgement marks it submitted; it moves to running on `turn/started` and becomes completed or failed on `turn/completed`. An uncertain acknowledgement remains unresolved for reconciliation.
- The dispatcher renews each active workspace lease to a 60-second horizon immediately before submit and every 10 seconds while a confirmed turn is active. A failed renewal or transport loss marks the attempt `needs_reconcile`, revokes the capability, quarantines the lease and drops the app-server. The workspace/path lock remains held.
- A `start_turn` acknowledgement error leaves the attempt `needs_reconcile` and does not retry or release the lease. R1's capability remains in place for an ambiguous submission; the lease's short renewed horizon later expires into quarantine while the attempt remains open.
- D1 resolution: existing-thread dispatch reads the persisted lease binding even if its prior capability was revoked. It may proceed only if that ID equals the exact current active lease; it then issues a fresh capability. A missing, changed or inactive lease still requires reconciliation.
- `list_workspace_recovery_cases` exposes quarantined lease and open-attempt metadata without canonical paths or prompt text. The unscoped local `reconcile_workspace_lease` action requires explicit confirmation that provider execution stopped, the exact set of open attempts with terminal outcomes and per-attempt reasons, plus an overall reason. It revalidates the linked-worktree/common-directory identity, commits attempt dispositions and lease release atomically, is idempotent for an exact replay, and performs no filesystem cleanup. Scoped role agents cannot use either tool. The unscoped local MCP does not authenticate an Owner and must not be remotely exposed.
- Recovery review corrections at `dd6bfc8a10e9500b477eb0f62ef8f7f195fa879e`: on Windows, the app-server is assigned to a kill-on-close Job Object before initialization; failure to configure or assign the job kills the direct child and refuses startup. Reconciliation now checks worktree identity inside the immediate transaction. Tests cover identity mismatch retaining the lock, invalid `created -> completed` resolution, a direct forbidden MCP tool call through the server handler, and rollback after an injected attempt-update failure. The local-MCP caller scope is documented in ADR-0024: local-only operator surface, not Owner-authenticated.
- Follow-up `ecf7d11329383fedae2b73dc6583100c5c9fafa8` also reads project/worktree paths and stored identity hashes from that immediate transaction snapshot, avoiding use of a path/hash read before acquiring the transaction.
- Provider-attempt creation rejects missing lease IDs and requires an active role capability bound to the same lease. If workspace/Git identity cannot be revalidated during provider admission, the lease is quarantined and its capability revoked.
- Main inbox provider starts are blocked because Main has no workspace-lease association. No interim exception was added.

## Limits and findings

- Main inbox starts remain blocked until the product has an exact Main workspace-lease model.
- The current adapters report unknown credential sources, so no real dispatcher request is eligible to spawn a provider.
- The live runtime remains unverified. Although source now schedules renewal, the built-in adapters report unknown credential sources and the Owner's runtime gate remains false; no provider turn exercised the loop. A lost acknowledgement has no confirmed turn ID, so the attempt stays open and its 60-second renewed lease transitions to quarantine on expiry rather than being renewed as confirmed live work.
- Semantic overlap is not modeled; the conservative lease policy serializes project writers. The permission manifest carries task scope, while the current Codex sandbox applies workspace-level access and does not enforce individual packet paths. Do not claim fine-grained path isolation.
- Claude's API audit found terminal resolution, release/revoke and claim arbitration fail closed. A direct revoke test and simultaneous-claim test remain absent. Claude's R-A/B/C findings are implemented in `dd6bfc8`/`ecf7d11` and await read-only review. The `provider_stopped_confirmed` input remains an operator assertion, not runtime proof. Job Object containment is Windows-only and has a narrow spawn-to-assignment interval; a provider process that escapes its job is not covered.
- Renewal-failure and transport-closed quarantine paths remain untested. A renewal failure currently clears all live-turn bookkeeping, and a completed turn can retain its lease for up to 60 seconds. A dispatcher stall longer than 60 seconds quarantines its active turns.
- Public in-process workspace admission validators are trusted APIs; the production dispatcher is the intended caller. Transient workspace/Git verification errors deliberately quarantine and require explicit reconciliation.
- M51b provider protocol/event integration remains incomplete. Current M42/M44 live evidence remains unknown. Fixture tests do not establish loaded or live behavior.
