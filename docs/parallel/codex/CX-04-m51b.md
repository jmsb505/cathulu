## Independent Codex semantic review at `4d671b1`

- **Finding: late start notifications can replace the active turn and hide its completion.** `CodexAdapter::map_message` unconditionally replaces `active_turns[session]` on every `TurnStarted`. If a delayed/duplicate start for an older turn arrives while a newer turn is active, the adapter now tracks the older ID. `map_notification` then drops the newer turn's completion because it differs from that stored ID. The dispatcher never sees the terminal event and retains/renews the newer turn's workspace lease until recovery or shutdown. Relevant code: `src/codex_adapter.rs` around `map_message` and `map_notification`.
- Add a regression case that starts turn A, completes A, starts turn B, then injects a late duplicate `turn/started` for A before B's completion. B's completion must still be emitted and persisted. The adapter should ignore a start notification that conflicts with an already active different turn.
- This is a source-level review finding only. No source or test was changed and no combined check was run; the registered CX-07 test integration remains behind Claude's fresh PAUSE WRITES / BUILDS acknowledgment. M51b semantic review and live acceptance remain open.
