# ADR-0024 — Product workspace leases and uncertain execution recovery

- Status: Accepted M52 safety baseline; Claude accepted dispatcher admission amendments A–D at `3444829134e7630c60b2e97b836cf5dbd7367300`, R1 at `6153cdc155a1ac3b10fc62b3e8b904e2b76e5bef`, and B1/D1 at `67266ab`. Claude accepted the recovery transaction, exact-set validation, replay and role denial in `c4f0fd8`, and required R-A/B/C. Codex addressed them in `dd6bfc8a10e9500b477eb0f62ef8f7f195fa879e` and refined R-B's transaction snapshot in `ecf7d11329383fedae2b73dc6583100c5c9fafa8`; independent review of the latter is pending. Product dispatch remains held off by explicit Owner direction; review does not activate it.
- Scope: Durable workspace assignment, role/session/attempt binding, credential-source eligibility and recovery for Cathulu-managed product execution.
- Depends on: [PLAN-020](../plans/PLAN-020-mixed-provider-personal-project-os.md) M52 and [PLAN-021](../plans/PLAN-021-manual-claude-codex-development.md) CX-05.

## Context

PLAN-020 M52 requires product writers to use exclusive workspaces, coordinators to stay read-only, and uncertain provider submission to block duplicate work until reconciled. The repository records provider sessions, attempts and workspace leases. The dispatcher still uses the Codex app-server transport, but its Worker and Project Manager paths now require exact lease, permission and credential admission before process, thread or turn starts. Main inbox starts remain blocked because Main has no lease association.

The Owner's same-directory Claude Code/Codex development arrangement is a separate, manual exception under ADR-0023. It is not a product workspace lease and does not establish provider isolation, authentication or runtime safety.

## Decision

1. Schema v22 records immutable lease identity and append-only lease events. A writer is a Worker with write access to an exact linked worktree of the registered repository, sharing its Git common directory. The worktree must be clean when the lease is acquired. Project Manager/coordinator access is read-only; writers cannot use the registered project root.
2. With no semantic-overlap admission model, permit at most one active or quarantined writer lease per project. This is conservative project-wide serialization; it does not claim that disjoint tasks conflict semantically.
3. Permit one active provider session for each logical `binding_key` across all providers. On v21 upgrade, conflicting active session rows are retained but marked `unknown`, so the system does not silently choose a winner. A new session can replace the role's session only after every other attempt for that role is terminal; replacement inactivates the old session and revokes capabilities tied to it.
4. Bind a provider attempt and role capability to the same exact lease. Provider execution is eligible only when the adapter reports a known credential source and the permission manifest explicitly allows it. Unknown or unapproved credential sources block.
5. Before each dispatch or Project Manager inbox `start_turn`, persist a provider attempt bound to the exact lease and capability. Mark it `submitted` only after a successful start acknowledgement, then track `running` and terminal outcomes from turn events. An uncertain acknowledgement, expiry, release, revocation, transport loss or known lease-renewal failure with an unresolved attempt moves it to `needs_reconcile`, quarantines the lease and revokes the capability. Retain role/path locks until explicit terminal reconciliation. Do not automatically retry the provider call or delete, move or clean a worktree.
6. Keep product dispatch behind the Owner's fail-closed runtime gate. Before every Worker or Project Manager provider start, resolve and validate the exact active workspace lease, workspace identity, role capability, permission manifest and known allowed credential source. Reject unbound capabilities and attempts. Once a capability is issued, revoke it on any refusal before calling `start_turn`; validate admission before marking the delegation dispatched. Preserve the capability after calling `start_turn`, even if its acknowledgement fails, because submission may be ambiguous. Renew the workspace lease immediately before submit and every 10 seconds while a confirmed turn is active, extending it to 60 seconds. If the acknowledgement is uncertain, keep the attempt open and let lease expiry quarantine it; do not retry or release the lock. Block Main inbox starts until Main has an exact lease model. Review is a prerequisite; only the Owner may decide whether to enable dispatch later. Do not migrate the live store or alter a running process as part of CX-05.
7. A revoked bearer capability does not erase the thread's durable lease binding. Reuse an existing thread only when that persisted binding equals the exact current active lease; issue a fresh capability for that lease. A missing, inactive, or different lease still requires reconciliation. This keeps R1's fail-closed revocation while allowing harmless pre-submit refusals to recover without manual reconciliation.
8. Provide a manual local recovery view and reconciliation action for quarantined leases. The action requires explicit confirmation that provider execution stopped, terminal dispositions and reasons for every unresolved attempt, and a lease-level reason. It revalidates the exact linked-worktree and common-directory identity inside the immediate transaction, records attempt dispositions and releases the lease atomically, and performs no filesystem cleanup. Role-capability agents cannot use these tools. The unscoped local MCP is a local operator utility and does not authenticate an Owner; the caller authorization remains the Owner/operator's responsibility, and the endpoint must not be remotely exposed.
9. On Windows, place the Codex app-server in a private Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`. Configure the job before spawning; assign the child before initialization or any turn submission. If configuration or assignment fails, kill the direct child and refuse startup. This contains the process tree after assignment if the dispatcher exits or crashes, but it is not proof of provider termination: a short spawn-to-assignment interval remains, other platforms have no equivalent containment here, and a process that escapes the job is not covered. Keep explicit operator confirmation mandatory during recovery.

## Consequences

- A dirty Owner worktree is never cleaned to satisfy a lease. A lost acknowledgement leaves the workspace unavailable until the attempt is reconciled.
- A v21 role with sessions active at both providers becomes temporarily unavailable (`unknown`) until one provider session is explicitly recorded.
- M52 is not complete until the admission, B1 and operator-recovery candidates are independently reviewed, semantic overlap is handled at admission, and authorized M42/M44 acceptance is recorded. Source and fixture evidence alone do not establish loaded or live behavior.
- The product dispatch gate remains false during review. This changes default behavior: an unset CATHULU_ROLE_DISPATCHER_ENABLED previously enabled dispatch, and now means off. CATHULU_ROLE_DISPATCHER_ALLOWED_CREDENTIAL_SOURCES and CATHULU_ROLE_DISPATCHER_NETWORK_ACCESS also default to deny. Current adapters report an unknown credential source, so real dispatch remains blocked before spawn.
- Main inbox events remain blocked because there is no exact Main workspace-lease association. A workspace/Git identity revalidation failure quarantines the lease and revokes its capability. The current Codex sandbox provides workspace-level access and does not enforce individual packet paths.
- The dispatcher renews an active turn's lease every 10 seconds to a 60-second horizon. Renewal or transport failure marks the attempt for reconciliation, revokes the capability, and quarantines the lease. The runtime remains unverified; the fail-closed gate stays false.
- Local operator recovery still requires provider-stop confirmation; its required field is an operator assertion, not proof. Windows Job Object containment reduces crash-orphan risk after assignment, subject to the residual limits in Decision 9. The unscoped local MCP is not Owner-authenticated and must remain local. Recovery updates audit state only and never cleans or moves a worktree.
- Workspace verification errors and successful verification with changed workspace/Git identity both quarantine the lease, but use distinct audit reasons. Verification errors can be transient; they still require explicit reconciliation because the system cannot prove the workspace identity.
- The public in-process validators `validate_provider_workspace` and `validate_role_provider_start` are trusted admission APIs. Production use must remain behind the dispatcher admission boundary; the current adapters still report `CredentialSource::Unknown`, so no provider start is eligible.
- Schema v22 requires the repository's normal backup and compatible-binary recovery rules. Existing v18 binaries cannot open this database.

## Evidence

The [CX-05 handoff](../parallel/codex/CX-05-m52.md) records the v22 migration, admission implementation, R1 cleanup behavior, B1/D1 review, local operator recovery behavior, R-A/B/C fixes, validation and open runtime limitations. No real provider was invoked, no live store was migrated, and no app-server or MCP process was started or reloaded; the Job Object unit test used only an isolated loopback child process.
